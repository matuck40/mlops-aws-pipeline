# Fatia 2 — O mesmo pipeline na AWS — Plano de implementação

> **Para agentes:** use superpowers:executing-plans (ou subagent-driven-development) para executar tarefa por tarefa. Passos em checkbox (`- [ ]`).

**Objetivo:** o pipeline da fatia 1 roda sozinho todo dia na AWS (ETL de ontem + previsão de amanhã) e a API responde por uma URL pública, tudo dentro do custo de alguns centavos por mês.

**Arquitetura:** o código Python continua o mesmo; muda **onde** ele lê/grava e **quem** o chama.

```
EventBridge Scheduler (todo dia, horário de Brasília)
        └─> Lambda volt-diario ──> ETL de ontem + previsão de amanhã ──> S3 (bucket volt-dados)
Internet ──> API Gateway (HTTP API, com throttling) ──> Lambda volt-api ──> lê previsoes/ no S3
```

O acesso a arquivos passa a ser feito por um módulo só (`volt.armazenamento`), com duas versões: pasta local (para testes e uso no Mac) e S3 (na nuvem). As etapas (`etl`, `previsao`, `api`) não sabem qual das duas estão usando.

**Stack nova:** boto3, moto (testes), Mangum, AWS SAM, AWS CLI.

**Spec:** `docs/SPEC.md` (etapas 0, 1, 3, 4 e 6, agora na AWS).

## Restrições globais

- Região `us-east-2`, arquitetura `x86_64` (a camada do pandas tem que ser da mesma arquitetura da função). Nada ligado 24h.
- Testes nunca acessam a AWS real nem a internet (S3 via `moto`; download do ONS injetado como na fatia 1).
- Credenciais: login temporário pelo CLI (`aws login` ou equivalente do Builder ID). **Nunca** criar chave de acesso permanente nem colocar credencial no Git.
- Configuração única: variável `VOLT_DADOS` — um caminho local (`data`, o padrão) ou `s3://nome-do-bucket`. Substitui `VOLT_DATA_DIR` (API) e `--base` (CLIs).
- "Hoje" e "ontem" sempre no fuso `America/Sao_Paulo` (a Lambda roda em UTC).
- A API não importa `etl` nem `requests`: `api.py` importa só de `armazenamento`, e cada Lambda tem o seu módulo de handler.
- O SAM não lê `pyproject.toml`: o pacote da Lambda vem de um `requirements.txt` gerado pelo `uv export`, **sem** o que a camada já traz.
- Fluxo Git: uma branch por tarefa → PR → CI verde + revisão por subagente → merge. Conventional Commits.

## Foco de revisão

1. **Fuso:** às 22h de Brasília já é "amanhã" em UTC. "Hoje" vem sempre de `America/Sao_Paulo`.
2. **ETL falhou, previsão não:** se o ONS ainda não publicou ontem, a previsão de amanhã (que usa D-6) ainda deve rodar. A Lambda diária roda as duas e só falha no final, informando o que deu errado.
3. **Gravação no S3 é atômica:** um `put_object` ou grava o arquivo inteiro ou nada. Não existe "renomear" no S3, e não precisamos dele.
4. **Permissão mínima, mas suficiente:** `volt-diario` lê e grava no bucket; `volt-api` só lê. As duas precisam de `s3:ListBucket`: sem ela, o S3 responde 403 (e não 404) para arquivo inexistente, e a API daria 500 em vez de 404.
5. **Tamanho e versões da Lambda:** pandas, pyarrow e numpy vêm só da camada; se entrarem também no pacote, passa de 250 MB.
6. **Testes com moto:** região e credenciais falsas definidas numa fixture, e o cliente boto3 criado só dentro do mock (nunca na importação do módulo). Senão o teste quebra no CI ou tenta falar com a AWS real.
7. **Limpeza:** `sam delete` não apaga bucket com objetos dentro, nem a pilha `aws-sam-cli-managed-default` (o bucket onde o SAM guarda os pacotes). O passo a passo para apagar tudo fica documentado no README.
